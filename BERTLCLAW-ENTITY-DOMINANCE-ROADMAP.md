# BertlClaw Entity Dominance Roadmap

Ziel: BertlClaw so konsistent und glaubwürdig über Website, GitHub und externe Erwähnungen hinweg aufbauen, dass Google, Menschen und potenzielle Kunden dieselbe klare Entity erkennen.

## 1. Canonical public entity

**Primäre Linie:**

- **Marke:** BertlClaw
- **Betreiber:** Dominic Reisenbichler, MSc.
- **Typ:** deutschsprachige Projekt- / Geschäftsmarke
- **Kernfelder:** Landingpages, Website-Texte, Positionierung, digitale Struktur, KI-gestützte Unterstützung
- **Regionale Einordnung:** Österreich / deutschsprachiger Raum

Diese Logik muss in allen öffentlichen Oberflächen identisch erscheinen:

- GitHub-Profil
- GitHub-Profil-README
- Website-Homepage
- Impressum / Datenschutz
- strukturierte Daten
- Repo-Description
- Social / Directory Profiles

## 2. Current strength signals already present

Bereits vorhanden und brauchbar:

- mehrseitige Website mit Leistungen und Use Cases
- Impressum und Datenschutz
- GitHub Pages als stabile Brand-URL
- JSON-LD auf zentralen Seiten
- konsistente Grundbeschreibung in mehreren lokalen Docs
- Logo-Assets für GitHub und Website

## 3. Main gaps still limiting search/entity strength

### A. Weak external corroboration
BertlClaw ist lokal gut vorbereitet, aber extern noch zu wenig durch andere Quellen bestätigt.

### B. GitHub identity not fully deployed
Lokale Texte für GitHub sind da, aber daraus entsteht erst dann Suchsignal, wenn Profil, Bio, Profile-README, Repo-Description und Pins wirklich live identisch sind.

### C. Missing public "About / Betreiber / Method" page
Die Website erklärt Leistungen gut, aber eine saubere zentrale Entity-Seite fehlt noch.

### D. Proof is still structurally stronger than publicly visible trust
Case-Logik und Proof-Ansätze sind lokal dokumentiert, aber noch nicht als saubere öffentliche Vertrauensarchitektur ausgespielt.
