# Offer + Close Checklist

Use before sending an offer and again before each close follow-up.

---

## A. Before sending the offer

### Offer clarity
- [ ] the main problem is described clearly
- [ ] the main bottleneck is named
- [ ] one recommended start is clear
- [ ] deliverables are concrete
- [ ] non-included items are explicit
- [ ] timeline is realistic
- [ ] pricing or price logic is clear
- [ ] the start CTA is obvious

### Scope discipline
- [ ] phase 1 is small enough to decide
- [ ] phase 1 is strong enough to matter
- [ ] the offer does not try to solve everything at once
- [ ] I would still want to deliver this exact scope

### Mobile-aware QA
For website / landing page / copy scopes:
- [ ] mobile reading flow has been considered
- [ ] mobile CTA visibility has been considered
- [ ] mobile section length / density has been considered

---

## B. Before close follow-up

- [ ] current status is visible
- [ ] last touch date is visible
- [ ] likely objection is named
- [ ] best downscope option is known
- [ ] the next message aims at a decision, not vague chatting
- [ ] there is a clear yes / no / pause path

### Pick the close intent
- [ ] clarify objection
- [ ] propose smaller phase 1
- [ ] confirm timing
- [ ] request decision
- [ ] pause cleanly

---

## C. After the decision

### If yes
- [ ] project setup starts immediately
- [ ] before-state capture is triggered
- [ ] proof setup is triggered

### If maybe / later
- [ ] reason is documented
- [ ] revisit date is set
- [ ] next message is not left vague

### If no
- [ ] loss reason is documented
- [ ] useful pattern / lesson is captured
