# Publication Workflow

Use this after delivery when turning project evidence into business assets.

## Step 1 — check evidence completeness
- [ ] starting situation written
- [ ] bottleneck written
- [ ] deliverables listed
- [ ] visible difference written
- [ ] before/after assets selected
- [ ] confidential material removed or marked

## Step 2 — choose the best proof angle
Pick one:
- [ ] visual before/after
- [ ] text clarity improvement
- [ ] stronger offer structure
- [ ] premium deliverable example
- [ ] documentation/organization system improvement

## Step 3 — confirm approval boundary
- [ ] internal only
- [ ] anonymous public
- [ ] partially identified public
- [ ] fully public

## Step 4 — produce derivatives
Create as applicable:
- [ ] website mini-case
- [ ] proposal proof snippet
- [ ] sales bullet list
- [ ] deliverable gallery entry
- [ ] social/email short version

## Step 5 — final claim check
- [ ] no invented metrics
- [ ] no implied guarantees
- [ ] all claims visible, approved, or measurable
- [ ] tone is specific and restrained

## Step 6 — log publication status
Record:
- published where
- published when
- which assets were used
- any client review completed
