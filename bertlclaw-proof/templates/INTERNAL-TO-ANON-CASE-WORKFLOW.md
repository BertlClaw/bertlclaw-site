# Internal Example -> Approved Anonymized Case Workflow

Tiny workflow for converting an internal proof example or project evidence pack into a publishable anonymized BertlClaw mini-case.

Use this only after anonymous public use is approved.

---

## Step 1 — choose the source case

Pick one internal example or real project with:

- a clear before/after or problem/solution contrast
- concrete deliverables
- at least one reusable proof asset
- a realistic safe public angle

If the source is only a demonstrator, treat it as a **structure donor**, not as something to publish directly.

---

## Step 2 — lock the publication boundary

Confirm and write down:

- anonymous public approved: yes / no
- text excerpts allowed: yes / no
- screenshots allowed: yes / no
- URL or domain mention allowed: yes / no
- industry/context mention allowed: yes / no
- client review of final anonymized draft required: yes / no

If any answer is unclear, stop here.

---

## Step 3 — replace demonstrator content with real approved facts

Convert from "internal example" to "real anonymized case" by replacing all placeholder/demo material with approved project facts.

Replace:

- project type
- context
- starting situation
- bottleneck
- BertlClaw work performed
- actual deliverables
- visible difference
- approved evidence references

Do **not** publish an internal example story unchanged.

---

## Step 4 — anonymize aggressively, then restore only necessary context

Remove or mask:

- client name
- company name
- logos
- domain / URL
- email addresses
- phone numbers
- exact location identifiers
- unique offer names or product names
- personal names inside screenshots or docs

Then add back only the minimum context needed for understanding, for example:

- "small local service business"
- "solo consultant"
- "small company with an unclear service page"

The public reader needs enough context to understand the problem, not enough to identify the client.

---

## Step 5 — build the mini-case draft

Use this structure:

- Project type
- Context
- Starting situation
- Core bottleneck
- What BertlClaw did
- Delivered
- Visible difference
- Evidence
- Safe public angle
- Approval status

Target for website version: **90-140 words**.

Target for internal full version: **150-300 words**.

---

## Step 6 — choose proof assets

Select only the strongest 1-3 proof assets:

- before/after screenshot pair
- before/after headline pair
- section structure comparison
- approved final deliverable excerpt
- final page screenshot

Do not attach everything. Compact proof is usually stronger than clutter.

---

## Step 7 — run the scorecard

Review the case with:

`bertlclaw-proof/library/publication/PUBLISHABLE-CASE-SCORECARD.md`

Rules:

- total score must be **18+**
- mandatory categories must be **2+**
- no mandatory fail condition may apply

If it fails, revise wording, evidence, or anonymization and score again.

---

## Step 8 — create the publication pack

Prepare these outputs:

1. **Internal full mini-case**
2. **Website mini-case**
3. **Proof atom extraction**
4. **Deliverable gallery candidate**
5. **Publication log note**

This keeps one approved case reusable across multiple surfaces.

---

## Step 9 — log status

Record:

- source project / source example
- approval boundary
- anonymization actions taken
- final score
- chosen publication surfaces
- publish date or next action

---

## Fast definition of done

A case is done when:

- approval is explicit
- internal demonstrator content has been replaced with real approved project facts
- anonymization is checked
- one strong public-safe mini-case exists
- 1-3 proof assets are selected
- scorecard passes
- publication status is logged
