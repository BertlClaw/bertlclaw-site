# Worked Review: Internal Mini-Case Example

Source reviewed:
- `bertlclaw-proof/library/internal-examples/mini-case-example.md`

Purpose:
- show how the scorecard should be used in practice
- demonstrate why internal examples are structure donors, not auto-publishable assets

---

## Scorecard review

### Approval clarity — 0
No anonymous-public approval exists. The file explicitly says:
- **Status:** internal demonstrator only
- **Public use:** not yet

### Starting situation clarity — 3
The example explains the website problem clearly and concretely.

### Bottleneck sharpness — 3
The bottleneck is precise: visitors had to do too much interpretation work.

### Work specificity — 3
The work steps are concrete and believable.

### Deliverable concreteness — 3
Deliverables are tangible and publication-friendly.

### Visible difference — 2
The difference is clear, though still qualitative rather than measured.

### Evidence quality — 2
The example names good proof types, but they are still example references rather than approved public assets.

### Anonymization safety — 2
The narrative is generic enough, but no actual screenshot masking or leak review is documented.

### Claim discipline — 3
Language is restrained and safe.

### Reuse value — 3
Very reusable as a future website/proposal/proof template.

**Total:** 24/30

---

## Why it is still not publishable

Despite a strong total, it fails the mandatory gates:

1. **Permission gate fails** — no explicit anonymous-public approval
2. **Evidence gate is incomplete** — proof assets are described, not assembled as approved publication assets
3. **Anonymization gate is not fully documented** — no masking checklist or asset-level review is attached

So the correct decision is:

**Decision:** internal only

---

## What would make it publishable

To convert this structure into a real anonymized public case, replace the demonstrator material with an approved real project and complete all of the following:

- record anonymous-public approval in the project approval file
- swap all example references for real approved evidence paths
- prepare 1-3 anonymized proof assets
- run the anonymization checklist on screenshots and text excerpts
- create a website mini-case draft using the approved facts
- rerun the scorecard and confirm all mandatory categories are 2+

---

## Practical lesson

A good internal example can score highly on clarity and usefulness while still being non-publishable.

That is expected.

The scorecard is not just about story quality. It is also about permission, evidence readiness, and publication safety.
