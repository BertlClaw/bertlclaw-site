# Internal Example Mini-Case

**Status:** internal demonstrator only  
**Use:** structure template for future anonymized client mini-cases  
**Public use:** not yet

## Project type
Landingpage clarification + offer structure cleanup for a small service business.

## Context
A local business had a basic website presence, but the main page did not explain the offer clearly enough. The business sounded capable, but visitors had to work too hard to understand what was being offered, for whom, and what the next step should be.

## Starting situation
- headline was generic and low-specificity
- service scope was spread across sections with weak order
- CTA existed, but the next step felt vague
- trust was implied, not made concrete

## Core bottleneck
The problem was not "no website." The problem was that the website created too much interpretation work for a first-time visitor.

## What BertlClaw did
- rewrote the hero so the offer, audience, and direction were understandable within seconds
- regrouped page sections into a cleaner reading order: problem -> offer -> proof -> next step
- tightened CTA logic so the contact action felt simpler and lower-friction
- added trust-oriented microcopy to reduce uncertainty before outreach

## Delivered
- revised hero + supporting subheadline
- new page structure / section order
- CTA copy and placement logic
- compact trust / objection-handling block

## Visible difference
The page moved from "probably useful, but hard to parse" to "clear enough to act on without extra explanation."

## Evidence
- **Before asset:** screenshot of original hero and first-screen section order
- **After asset:** screenshot of revised hero and updated section sequence
- **Text/structure comparison:** before/after headline pair + old vs. new section map
- **Final artifact or URL:** internal draft or shipped landingpage screenshot

## Best proof atoms to reuse
- hero before/after
- CTA logic upgrade
- offer-structure cleanup

## Safe public angle
"BertlClaw turned an unclear service page into a clearer landingpage structure with a stronger first message and a simpler next step."

## Risk notes
- **Overclaim risk:** do not claim performance lifts or conversion increases without measurement
- **Confidentiality risk:** remove brand name, contact data, and any unique local identifiers if published
- **Weak evidence areas:** trust improvement is real but partly qualitative unless supported by user feedback or inquiry data

## Why this is a good future case
It is relatable, visually demonstrable, and closely tied to BertlClaw's actual offer: making digital communication and structure clearer so businesses become easier to understand.
